# GitHub Pages版 受入基準と設計判断

## 採用構成

- React + TypeScript + Viteによる静的Webアプリ
- 計算、ファイル読込、帳票生成はブラウザ内で完結
- GitHub Actionsでテスト・ビルド後、GitHub Pagesへデプロイ
- Python + Streamlit版は計算仕様の参照実装として維持

## GitHub Pagesを採用した理由

このアプリは認証、データベース、サーバー上の永続化を必要としません。貨物情報を端末外へ送らず、無料の静的ホスティングで安定運用できることを優先し、GitHub Pages版を公開用の主画面とします。

Streamlit版のAIダブルチェックは、APIキーをブラウザへ安全に保持できないため移植していません。将来必要になった場合は、AI処理だけを認証付きサーバーAPIとして分離します。

## 受入基準

### 入力

- CSV、TSV、Excelの先頭シートを読み込める
- 日本語・英語の代表的な別名ヘッダーを正規化できる
- 表上で追加、編集、削除、複数行のmm→cm変換ができる
- 必須値、数値範囲、数量、重複IDを実行前に検出できる
- 数式で始まる文字列を帳票出力時に無害化する

### 計算

- 必要本数の見積り、指定本数での検証、指定コンテナへの手動配置を選べる
- 手動モードはパッキングリストをピース展開し、コンテナ内寸と同じ縮尺のボックスをドラッグまたは選択クリックで床面へ配置できる
- 手動配置は上面図を初期表示し、チェックボックスで側面図への切替または上面図・側面図の併記ができる
- 手動配置は5cm単位で記録し、90度回転、位置調整、未配置への戻しに対応する
- 手動配置時に重なり、床面範囲、内寸高、Payload、混載不可を検査する。高さ差100cm以上の隣接は拒否せず、結果の注意事項として表示する
- 回転、段積み、上積み許容重量、混載不可IDを考慮する
- OOG、入口通過、冷凍・冷蔵、OT、FR、在来船検討を判定する
- 固定本数モードでSTANDARD・SPECIALの全指定を使用する
- Payloadは貨物重量、車両総重量目安は貨物重量＋風袋で監査する
- 偏荷重と重量集中をコンテナ別に表示する
- 同型コンテナが複数ある場合、寸法・混載・Payload制約内で貨物重量差を縮小する
- 前後方向は原則として大きい貨物をトラック側（x=0）、小さい貨物をドア側へ配置し、異寸法貨物を重量バランスだけで入れ替えない
- 標準コンテナは、現在の床列に入る後続貨物をすべて試し、床面を極力埋めてから段積みへ進む
- 高さ差100cmは注意目安とし、配置不可条件にはしない。トラック側から背の高い貨物順になるよう努力する
- OT・FRは標準コンテナの大型順を必須としない。特にFRはデッキ中心に対する点対称性と重量重心を評価して中央寄せする
- 全標準貨物の総容積・総重量が20GP容量内で、1本へ実配置できる場合は20GPを選び、判定値を選定根拠へ表示する。それ以外は40HCを基準に見積もる
- 段積みのない同寸法貨物は左右へ分散し、同寸法内で安全に移動できる範囲だけ重量バランスを調整する

### 結果

- 推奨構成、配置率、貨物重量、容積、要確認件数を表示する
- コンテナ別の上面配置図とKPIを表示する
- 40HCの各バンプランに、同じ配置で40GPへ代用可能かを内寸・入口寸法・Payloadの判定理由とともに表示する
- 貨物重心は貨物表示を隠さない小さな無塗り十字で示す
- 上面配置図でOWの左右超過量を寸法線、OHの超過量をバッジとして注釈する。極端なOWは実超過量を保持したまま「～～」線で描画を省略する
- 同一貨物を段積みした箇所は、隣接する同じ段数の列をまとめて「4段 × 3列」のように注釈する
- 選定理由、OOG、未配置貨物を追跡できる
- CSV、Excel、印刷・PDF保存用レポートを出力できる
- 印刷時はQRコードの掲載有無を選択でき、既定はモノクロ、必要に応じてカラーへ切り替えられる
- 積載済み個数を `n / n PCS` で表示する
- CLPにコンテナ別および全コンテナ合算の総個数・総重量・総容積を表示する
- 手動配置から既存のCLP、CSV、Excel、印刷・PDF帳票を作成できる
- 貨物、計算条件、指定本数、コンテナ仕様を圧縮した共有URLとQRコードを生成できる
- QRのデータ部が85モジュールを超える場合は最大8枚へ自動分割し、順不同・重複読取に対応する
- 共有URLから入力を検証して復元し、自動的に再計算できる

手動配置座標は現行の共有URL・QRには含めません。手動プランはCSV、Excel、印刷・PDF帳票で保存します。

印刷QRは40 mm角、四辺の余白は4モジュールとします。分割判定の上限をデータ部85モジュールとすることで、余白込み93モジュールに対して1モジュール約0.43 mmを確保します。分割QRはLoadPilot内の「QR読込」で結合し、全パーツのチェックサムが一致した場合のみ復元します。標準外コンテナ仕様は従来どおりプラン本体と別系統で分離し、照合IDでも一致を確認します。

### 公開品質

- PC、タブレット、スマートフォン幅で操作できる
- 通常URLの再読込時に貨物データを残さない（共有URLは `#plan=` 内のデータを復元する）
- テスト、TypeScript型検査、production buildをCIで実行する
- GitHub Pagesのサブパス `/container-loading-planner/` でアセットを読める

## 計算上の限界

配置は棚割り方式のヒューリスティックであり、数学的な最適解を保証しません。以下は別途確認が必要です。

- 床の点荷重、固縛、荷重分散、荷役機材、作業順
- 実機材の内寸・入口寸法・最大積載重量
- 船社ごとのOOG許容値、機材在庫、運賃、船積可否
- 道路法令、特殊車両通行許可、輸送経路
- 危険品、温度管理、品目固有の混載制限
